## 设计方向与依据

本轮不沿用待选 1 的视觉目标。新方向是低饱和青绿和浅暖灰的文件工作台：左侧提供稳定导航，文件在主区，底部集中呈现任务进度。以更轻的边界、稍宽的文字间距和明确的状态变化减少无关刺激。**配色只能表达舒适阅读的设计意图，不能证明减少眼疲劳或有护眼效果**；实际舒适度由用户体验判断。

- [Microsoft YaHei UI / Microsoft YaHei](https://learn.microsoft.com/en-us/typography/font-list/microsoft-yahei)：面向中文屏幕阅读的系统字体。中文优先选择 UI 字形，不下载大字体包；保留 Windows 清晰度与轻量部署。字体并不是仅凭名称就优于其他字体，仍须检查实际字号、回退与截图。
- [Windows typography](https://learn.microsoft.com/en-us/windows/apps/design/signature-experiences/typography)：正文 Regular、标题适度加重，默认左对齐，长名称省略；不把 WinUI 的默认可变字体行为当成 WPF 已实现结果。
- [Windows motion](https://learn.microsoft.com/en-us/windows/apps/design/signature-experiences/motion)：反馈应直接、短暂，维持视觉关联。借鉴时间尺度，采用 WPF 原生动画；不引入 Lottie/网页引擎。
- [Progress controls](https://learn.microsoft.com/en-us/windows/apps/develop/ui/controls/progress-controls)：可计算进度用确定进度条；不确定过程不得虚构百分比。真实产品接入时进度必须来自现有工作进程，不能照搬原型演示时间。
- [WPF animation](https://learn.microsoft.com/en-us/dotnet/desktop/wpf/graphics-multimedia/animation-overview)：使用依赖属性与动画时钟；动画结束回到真实目标值，取消/关闭释放任务，关闭动态效果保留文字和数值。
- 图标、Files/NanaZip/WPF 可实现性参考复用已有 `design-system/next-20261017/DIRECTION.md` 的原始来源；所有功能图标仍统一 Fluent Regular 20，保留源 SVG、MIT、固定提交和哈希。没有混用新图标集。

## 动画参数与语义

- 进度：确定进度条 6 DIP，数值改变时 220ms Cubic EaseOut，从当前视觉值过渡到最新真实目标；不增加装饰条纹、闪烁、反弹或自动循环。数字和文字立即反映逻辑值。
- 任务反馈：用户触发演示时 170ms Opacity 0.65→1，完成后静止，不做持续呼吸。窗口内不会同时堆叠多项装饰动画。
- 减少动态效果：遵循 `SystemParameters.ClientAreaAnimation`，设置改变及时响应；也可手动关闭。关闭会立即移除动画时钟，进度跳到当前逻辑值，百分比和状态继续更新。系统关闭时不以应用开关强行打开。
- 真实产品：只在实际服务提供可用进度时显示百分比，未知过程保持文字/不确定状态；保持全队列暂停语义，不新增单任务暂停或虚构速度/剩余时间。
- 原型解压是**真实生成 ZIP 的内存读取和字节核对，加人为延时演示**，无磁盘交付，所有任务画面带“演示”。不将它当作正式 7-Zip 解压能力/速度；62% 静态图为受控状态。
- 动画证据来自隔离 x64 中实际 WPF 任务区逐帧编码的 GIF，保留原始文件和报告。CI 为检查动画可模拟“允许动态效果”，与真实 Windows 设置分开记录。静态 PNG 不作为动画通过证据。
