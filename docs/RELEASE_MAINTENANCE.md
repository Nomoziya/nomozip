# 轻量候选打包与阶段收尾

在项目根目录准备既有 .NET SDK、官方引擎、worker、NSIS 与 Python 3 后运行：

```powershell
./scripts/build-release.ps1 -OutputDirectory artifacts/release-local-new
```

命令默认在新的 `artifacts/release-build/随机目录/payload` 构建共享运行库版本，不覆盖本机正式启动入口。已有对应当前源码版本的轻量载荷，可用 `-ApplicationDirectory artifacts/notification-candidate` 复用；Python 不在 PATH 时用 `-Python 完整路径`。安装器数值版本与显示版本读取实际 EXE 并核对项目，不再使用旧固定版本。公开构建不允许版本覆盖；隔离升级夹具仍可在 `ValidationRoot` 下用两个人工版本模拟升级。

输出必须是 `artifacts/` 下尚不存在的新目录；每次选择新路径，旧目录及旧资产不覆盖。目录内只放轻量安装 EXE、轻量 ZIP、源码 ZIP 和 `SHA256SUMS.txt` 四项。报告默认在该目录外的 `目录名-validation.json`，可用 `-ValidationReport` 指定。若已有上传源码的 checkout，可加 `-PublishedSource .tools/publish` 核对源码包与该 checkout；普通克隆不需要此选项。

复核包括精确资产/源码允许清单、CRC、SHA-256、安装器与构建输入一致、载荷与当前输入逐字节一致、源码与当前文件一致；拒绝随包运行库、密码库/私密材料及未发行的菜单身份原型。两份 ZIP 创建前同时检查输入和已有目标，避免旧源码包已占用时只产生新软件 ZIP。检查失败保留诊断，不覆盖或自动清空已有目录。

本工具负责本地打包与一致性，不能代替产品的引擎/业务/桌面/升级 CI。报告的 `validationScope` 明确该边界；不会发布 GitHub Release、签名、变更更新渠道或替换用户安装。产品验收与阶段状态见 [验收与交接](ACCEPTANCE.md) 和 [规划](ROADMAP.md)。既有 0.2.0-preview.14 四项候选资产保持不变，工具演练另放 `artifacts/release-maintenance/`。

维护脚本检查使用独立合成源树与载荷、真实 NSIS 编译和默认/复用两种命令入口，检查版本、旧包保留、校验被修改、源码缺漏、额外文件、私密材料及运行库拒绝。CI 接在既有轻量安装/旧版升级步骤之后；脚本本身只构建，不在用户机器实际安装或发送通知。结果为 `artifacts/release-maintenance-validation.json`。引擎跟进与 RSA 更新打包继续使用 [现有更新维护流程](UPDATES.md)，不改固定公钥或降低兼容矩阵。

## B 阶段交接边界

| 工作包 | 已实施并有代理证据的范围 | 保留的后续或环境项 |
| --- | --- | --- |
| B1 | 所选文件/文件夹解压与最小只读预览技术验证 | 拖出包内文件、完整文本/图片预览界面仍未实现 |
| B2 | 密码分组/来源/去重、SHA-256 与清单、ZIP 文件名编码 | 不推断云同步、暴力密码恢复或其它格式写入能力 |
| B3 | PMv2/DPI 与工作区适配、来源标记、传统菜单回归 | 物理不同 DPI 多屏与真实 SMB 来源行为仍缺环境；Windows 代码签名与第一层原生菜单公开部署移出范围 |
| B4 | 重排/单项重试、最多两项受控并发、当前进程暂停/继续、可选整批成功通知、轻量打包维护 | 真正跨重启续作未实现；用户系统上的可见通知体验尚未验证 |

上述范围完成后可继续 C / F08 压缩方案预设；不把技术原型说成完整预览，不把当前进程暂停说成跨重启恢复，也不把代理的几何/回调检查说成真实多屏或实际通知体验。待环境项独立保留，不要求用户重复全部已通过的功能测试。公开正式版仍为 0.1.0，所有 0.2.0 候选只在本地；正式发行另行决定。
