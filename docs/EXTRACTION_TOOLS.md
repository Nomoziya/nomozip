# 解压规则与独立校验

开发候选 0.2.0-preview.4 增加 A4 常用解压操作；公开正式版仍为 0.1.0。默认保持原来的自定义目录直接解压，不自动打开结果位置。

## 目录规则

在解压页点击“解压规则…”。独立窗口提供位置、目录结构、命名和完成操作；主页面仍保留任务列表、设置卡片与固定底栏。

- 位置：自定义目录、每个压缩包所在目录、桌面、文档。自定义框可从最近五个使用的位置选择，也可输入完整路径。
- 目录结构：“直接放入”沿用现有行为；“每包新建目录”隔离各包；“智能目录”根据真实内容选择目标。
- 智能目录：单个文件或只有一个根文件夹时直接放入所选位置，避免重复套目录；散放多项或多个根目录时新建容器。原有根文件夹合并时仍遵守主页面的询问、跳过或覆盖策略。
- 容器命名：压缩包名，或“压缩包名_日期”。分卷 `name.7z.001` 的容器名为 `name`。这些命名仅用于实际需要新建的容器。
- 容器重名：“创建新编号目录”默认使用 `name (2)`、`name (3)`，不会复用已有文件或目录；“合并”进入已有目录，并遵守同名文件策略。若同名对象是文件，合并会显示输出错误并保留该文件。

行为借鉴 [Bandizip 智能解压规则](https://www.bandisoft.com/bandizip/help/auto_dest/)和 [PeaZip 的智能目录及输出选项](https://peazip.github.io/how-to-extract-rar-zip-archives.html)，自主实现于现有 Core/WPF 技术栈，无新增第三方运行组件。

右键菜单的“解压到所在目录/同名文件夹”继续按该入口明确的目标执行，不被其它目录预设改写。“浏览目录”解除本次右键的逐包目标，改用统一自定义位置；“解压规则…”应用所选规则。实际成功目标记录在当前任务，之后改变输出框不会改写已完成任务的位置。

## 校验压缩包

选择任务后点击“校验压缩包”。校验使用官方引擎读取数据，支持自动尝试密码库、手动补充、同包多密码、跳过尝试和取消；不会输出解压文件、更新密码库使用记录或保存输入的密码。

结果显示“校验通过”“校验未通过”或“已取消校验”，可以打开“校验结果”查看成功数量及失败条目。成功校验不会把未解压的任务标为“已解压”；校验已解压的任务保留其原完成状态和结果位置。密码不匹配与部分格式的数据损坏可能共享错误码，会如实显示歧义；缺卷、损坏、取消分别保留引擎结果。格式不提供校验值时，测试只能验证数据可读取性。

## 打开结果位置

可在规则窗口勾选“整批解压成功后打开结果目录”。整批完整成功才触发；任何任务失败或取消都不自动打开。一个目标直接交给资源管理器，多个不同目标显示位置列表，每次只打开所选目录，不批量弹出窗口，也不打开包内文件。

底栏“打开输出目录”优先打开所选已完成任务的实际位置；没有所选结果时可选择本批次其它成功位置，或手动打开原输出目录。

## 设置与验证

目录规则与最近位置保存在原有本机设置文件中，旧版缺少这些字段时使用原行为。未知设置版本或未知规则枚举保持原文件，不自动覆盖。右键逐包目标不持久化为目录规则。

`tests/ExtractionToolsValidation` 使用 26.03/26.04 的真实引擎与合成压缩包，验证单文件、单根目录、多根、编号、合并/跳过/覆盖/取消、缺卷、损坏、多密码和无输出/无密码库修改。`ArchivePassword.exe --validate-extraction-tools <项目目录>` 使用独立合成资料验证实际 WPF/UIA 绑定、主题、窄窗口、规则保存、旧设置、手动密码、结果选择及完成触发；Explorer 调用使用替身，实际物理多屏和真实辅助语音的原有范围保持不变。报告分别为 `artifacts/extraction-tools-validation.json` 与 `artifacts/extraction-tools-ui-validation.json`，均接入 Windows CI。
