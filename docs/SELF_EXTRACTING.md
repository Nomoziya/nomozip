# 7z 自解压包

开发候选 0.2.0-preview.18，公开正式版仍为 0.1.0。

在“压缩”页选择 7z 和“不分卷”，勾选“创建自解压包（EXE）”。原来以 `.7z` 结尾的目标会切换为 `.exe`，也可重新选择保存位置。可继续设置压缩级别、密码和文件名加密。ZIP 或分卷模式会禁用该选项并说明原因；切换到这些模式会取消自解压并恢复对应扩展名。

接收者运行生成的 EXE 后，使用官方 7-Zip 自解压窗口选择位置并在需要时输入密码；无需安装 nomozip、7-Zip 或 .NET。本期只解压，不加入安装脚本、自动执行包内程序或删除原始文件的配置。程序中的“添加压缩包”也接受 EXE，通过引擎浏览、校验和解压，不执行它；包内修改保持只读。

生成使用与当前引擎相同版本的官方 `7z.sfx`，原样前缀连接新的 7z 数据。软件先在目标目录创建临时内容和 EXE，完整测试最终 EXE并核对清单后交付；已有目标需要明确确认，正常取消、候选损坏和提交失败保留原文件，清理本次临时文件。密码仅在成功后按用户选择保存并关联最终 EXE；下次可在软件中自动尝试。

## 模块与更新

模块取自对应版本官方 x64 安装包，附带现有 7-Zip 许可与源码链接。26.04/26.03 的 GUI 模块都是 215552 字节，PE 架构为 x86；这是官方分发内容，产品与 DLL 仍为 x64。未自行重编译模块或引擎。

随包模块由引擎 manifest 的 `sfxSha256`、模块版本及 PE 结构校验；内置匹配失败会阻止自解压创建，不影响普通归档功能。维护脚本从官方安装器提取同版模块，启用前运行实际独立 EXE 测试，绑定模块、DLL 和报告哈希。

更新包沿用原有 schema 1 和五个 ZIP 条目，不新增外部文件或使用未签名下载。模块以版本、SHA-256 和 Base64 字节放入 `compatibility-report.json`，该文件仍由现有 manifest 哈希及 RSA 签名保护；签发前保留原客户端的 1 MiB 记录大小限制。旧客户端可继续校验和安装引擎，新客户端从签名记录读取匹配模块。旧包没有模块时，只允许复用同版本且 DLL 哈希相同的内置模块；没有匹配模块时禁用自解压，不使用其它版本代替。

Windows 安装包代码签名不在本项目验收范围，未采购证书或签名安装器。上述更新包 RSA 验证继续保留，测试仅使用独立合成密钥，不访问生产私钥。

## 验收

`tests/SfxValidation` 对 26.04/26.03、仅存储/标准/最高压缩、无密码/内容加密/文件名加密进行专项测试。使用不可见、从不切换到的临时 Windows 桌面运行生成的 EXE，限定 PATH 为系统目录，不借助外部解压工具；密码参数是固定合成夹具，产品创建流程仍通过父子管道传递密码。测试真实输出字节、中文/空目录/空文件、包内脚本不执行、错误密码、取消、替换、损坏候选、实际提交锁与原始输入保留。局部 Windows 沙箱拒绝 CreateDesktop 时，在已批准的受限测试范围外运行这项测试，不修改用户桌面。

`--validate-sfx` 使用独立库及屏幕外 WPF 窗口，调用实际 UIA 选项和创建按钮，覆盖扩展名、互斥选项、普通/高对比度与窄窗、损坏模块、密码成功关联、拒绝/批准替换、自动解压、只读修改限制和返回普通压缩。更新验证另覆盖签名模块独立读取、错误哈希/版本/Base64、旧包有/无匹配模块及实际 EXE 创建。

本地专项与界面检查已通过，最终计数、完整 CI 和轻量资产以项目计划最新交接为准。未来官方版本尚未实测；必须通过相同兼容矩阵才启用或签发。
