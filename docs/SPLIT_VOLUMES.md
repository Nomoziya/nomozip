# 分卷压缩

开发候选 0.2.0-preview.17。公开正式版仍为 0.1.0。

在“压缩”页添加文件或文件夹，选择完整的新包路径、格式和压缩级别。分卷默认“不分卷”；可选择 100 MiB、1 GiB、4 GiB，或输入正整数并选择 MiB/GiB。1 MiB 为 1048576 字节，1 GiB 为 1073741824 字节，自定义最大 1 TiB。界面不接受小数、零或负数。

7z 与 ZIP 均支持分卷和现有密码加密；7z 支持文件名加密，ZIP 沿用 AES-256/ASCII 密码限制。分卷大小是每个输出文件的上限，最后一卷通常较小；小包也生成 `.001` 首卷。文件名例如 `照片.7z.001`、`.002`，超过 999 卷继续使用 `.1000`。

传输时将所有分卷放在同一目录，保持完整名称。解压、查看内容或校验时选择 `.001` 首卷，软件直接读取实际包内条目，不要求先生成合并文件。其它分卷会提示选择首卷；缺卷或校验失败不报告成功。官方 7-Zip 也能读取所生成的分卷；读取官方 CLI 生成的同类分卷纳入兼容测试。本功能不是 PKZIP `.z01` 多磁盘 ZIP 创建，也不是分卷已有归档的编辑。

创建前若目标基础文件或任意同名前缀数字分卷已存在，会保留它们并要求新名称或目录，不自动替换一组分卷。软件在目标目录中的独立临时目录生成全部分卷，完整测试并核对实际清单后，逐个移动到目标位置。正常取消或提交失败会清理本次拥有的分卷；出现外部同名文件时不会覆盖。多文件提交不具备断电时的组原子性，本期不承诺跨重启恢复或续传。需要足够空间容纳临时分卷；原始输入不会删除。

加密创建成功后才按现有选择保存密码，关联实际 `.001` 首卷；下次可自动尝试。失败不保存本次新密码。成功后“打开所在目录”可用，密码输入仍沿用掩码窗口。

## 实现与验收

沿用 WPF/.NET 10、现有主题和 C++ worker，无新增运行依赖。原生逻辑输出流按分卷大小支持随机寻址，供官方 7-Zip 写入/回写文件头；逻辑输入流按连续分卷映射读取，每次仅保留一个文件句柄。参考官方 SDK `CPP/7zip/Common/MultiOutStream.h` 和 `CPP/7zip/Archive/Common/MultiStream.cpp` 的可寻址多流方式，未引入额外命令行密码传递或完整合并中间文件。

数据矩阵 `tests/VolumeValidation` 使用 26.04/26.03，覆盖格式、加密、中文目录/空文件/空目录、直接解压和官方 CLI 双向互读、重组校验、缺中间/末卷、错误密码、取消、提交碰撞、损坏临时卷、超过 999 卷编号、孤立旧卷及分卷只读编辑。实际 WPF/UIA `--validate-volumes` 使用隔离密码库，覆盖默认/预设/自定义与输入恢复、高对比度/窄窗、真实创建按钮、成功密码关联、自动解压及返回普通压缩。

引擎更新候选须通过新增分卷矩阵，绑定精确 DLL 与报告哈希，失败保持禁用；准备、复核和更新包签发都保留该证据。Windows 代码签名不在验收范围，本轮不访问生产更新私钥。

本地数据与界面测试已通过；完整 CI、最终计数及轻量候选资产以项目计划最新交接记录为准。
