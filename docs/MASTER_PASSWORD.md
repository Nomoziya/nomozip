# 主密码与空闲锁定（0.2.0 开发候选）

默认不启用主密码，现有密码库继续由当前 Windows 用户加密保护。开启后，密码库文件和应用的恢复副本都需要主密码解密；重新打开软件时从锁定状态开始。此功能使用现有 .NET 能力，未加入运行组件。

## 使用

1. 建议先在密码库中导出独立加密备份，妥善保存备份及其独立密码。
2. 在“设置 → 密码库保护”选择“开启主密码”，输入并确认至少 12 个字符的主密码，可使用中文。
3. 在密码库页点击“锁定密码库”或“解锁密码库”。锁定后列表和应用缓存清空，编辑、导入导出、去重和自动取用不可用；仍可手动输入解压密码，但不能保存到锁定库。
4. 空闲锁定默认 5 分钟，可选择不自动锁定或 1/5/15/30 分钟，点击“保存锁定设置”。按本程序内的操作计时，任务期间延后，任务完成后检查锁定；不会撤回已交给正在运行工作进程的密码。
5. 更改或关闭主密码均需验证当前主密码。关闭后恢复 Windows 用户加密；新主密码生效后，旧主密码不能打开当前库或应用恢复副本。

设置页的“恢复最近一次保存”用于恢复本机 `.bak`，开启主密码时需要对应主密码。它也可修复已损坏的 APV2 正文，恢复文件须完整通过解密和数据校验。它不是忘记主密码后的重置通道。

## 忘记主密码

用户已选择独立加密备份恢复，不提供重置通道或恢复码。在“设置 → 密码库保护”点击“忘记主密码：从独立备份恢复”，选择事先导出的 `.nvault`、输入其备份密码、预览记录，再确认创建新库并设置新的主密码。错误密码、取消或未确认不会替换当前库。

恢复保留当前锁定文件及其恢复副本的原始加密字节，另存为 `passwords.apv.before-recovery-随机编号` 及对应 `.bak`，完成后在界面显示路径。恢复结果只含备份中的记录，备份之后的新增/修改不在其中；原压缩包关联不在便携备份中，不会被猜测重建。没有可用备份及其密码，无法恢复原库。新主密码不能解开原始保留副本，若之后想读取它仍需原主密码。

## 数据格式和迁移

旧 APV1 在不开启主密码时保持原行为。开启后使用 APV2：固定版本与 PBKDF2-SHA256 参数（600000 次）、随机 16 字节盐、12 字节随机 nonce、AES-256-GCM 的 16 字节验证标签；文件头参与认证。主密码实际参与密钥派生，不保存在设置或日志中。每次写入使用新的 nonce；启用/更改重新生成盐，当前会话仅持有可清空的派生密钥。

迁移先生成并验证新密文，再提交恢复副本和原子替换主文件；操作异常时回滚恢复副本，已测试实际文件写入失败及取消。启用成功不留下可用 APV1 的应用 `.bak`。未知格式、正文/认证头损坏或不匹配的密码不会被当作空库。旧正式版不能打开 APV2，回到旧软件前应先在支持主密码的版本中授权关闭主密码，或使用独立备份迁移。

锁定清空可写密钥字节并释放记录/待压缩密码引用；不承诺 .NET 不可变字符串或其它进程已经接收的密码立即从全部内存消失。系统会话锁定不是本期触发条件，原有外部备份、文件系统历史副本不会被追溯重新加密。

实现依据：[微软 AES-GCM API](https://learn.microsoft.com/en-us/dotnet/api/system.security.cryptography.aesgcm.encrypt?view=net-10.0)、[PBKDF2 API](https://learn.microsoft.com/en-us/dotnet/api/system.security.cryptography.rfc2898derivebytes.pbkdf2?view=net-10.0)。沿用已验证的备份数据规则与 .NET 密码学能力，没有增加新加密依赖。
