# 密码库加密备份与迁移

开发分支新增备份状态（未发布）：密码库工具栏下方显示上次成功独立导出的时间、此后新增数量或修改提醒，并提供“导出备份”。没有记录时提示建议备份；查看、复制或成功使用密码不会被算成内容修改。只有实际导出成功后更新提醒记录，取消、失败和导入都不将本机记录当成新备份。记录使用当前Windows用户的DPAPI保护，锁定库后隐藏内容状态；它证明曾成功导出，不保证用户保存的备份文件此后仍存在。旧备份不自动推定已登记，密码库自身的最近一次写入恢复副本也不冒充独立备份。验证范围见CURRENT_STATE。

此功能自 0.2.0-preview.1 开发候选加入，已完成代理验收；公开正式版 0.1.0 不包含此入口。本地候选位于 `artifacts/release-0.2.0-preview.1/`，未发布新的正式版。

## 操作

1. 打开“密码库”，点击底部的“导出备份”。保存为 `.nvault` 文件。
2. 设置至少 12 个字符的备份密码并再次确认，可使用中文。导出的是整个密码库，不受当前搜索筛选影响；名称、备注和密码都在加密内容中。
3. 在目标电脑或 Windows 用户中打开 nomozip，进入“密码库”，点击“导入备份”并选择文件。
4. 输入备份密码，查看名称、备注和预计新增/跳过数量。默认按密码内容跳过重复项，保留本机记录；也可选择保留两份。
5. 点击“确认导入”。新记录由目标 Windows 用户重新加密保存，之后可自动尝试启用的密码。

备份密码与压缩包密码是不同用途。请记住备份密码，忘记后无法恢复该备份。备份文件可单独复制到其它电脑，不依赖导出者的 Windows 登录信息。

## 数据规则

- 只备份密码记录：ID、名称、密码、备注、自动尝试开关、创建时间和最近成功时间；不迁移机器上的压缩包路径关联。
- 导入是追加合并，不清空或替换现有库。现有记录及关联保持不变；同 ID 的不同密码生成新的 ID，不覆盖原记录。
- 默认按密码内容精确、区分大小写判重，包括备份内部的重复。保留两份时也保留各自的名称、备注和启用状态。
- 导入全为重复项且选择跳过时不写盘；预览取消、错密码、文件损坏、暂不支持的版本均不写入密码库。
- 有新增内容时，一次合并后原子保存，保留原先的本机恢复备份规则。写入失败保留旧文件。导出同样先写临时加密文件，再原子替换旧导出文件。
- 本机 `passwords.apv` 和 `.bak` 仍受当前 Windows 用户的 DPAPI 保护，不能把直接复制它们当作跨电脑迁移。导出入口禁止覆盖这两个本机文件。
- 导出最多 10,000 条记录，文件最多 16 MiB；不提供明文 CSV/JSON 导出。本机恢复备份与 `.nvault` 迁移备份是不同用途。

## 格式与维护

采用 .NET 自带的 [AES-GCM](https://learn.microsoft.com/en-us/dotnet/api/system.security.cryptography.aesgcm?view=net-10.0) 和 [PBKDF2](https://learn.microsoft.com/en-us/dotnet/api/system.security.cryptography.rfc2898derivebytes.pbkdf2?view=net-10.0)，无需新增运行组件。借鉴 [KeePass 的导入/导出工作流](https://keepass.info/help/base/importexport.html)，没有实现其 KDBX 兼容格式或引入整个密码管理器。

格式 v1：44 字节认证头、16 字节认证标签、加密 JSON。认证头为 `NOMOVLT\0`（8 字节）、小端版本 1（4）、PBKDF2 次数 600,000（4）、随机盐（16）、随机 nonce（12）。密钥为 PBKDF2-HMAC-SHA256 生成的 32 字节 AES 密钥。整段头参与 GCM 认证；标签 16 字节。每次导出生成新的盐和 nonce。解密成功后校验 JSON 版本和记录，才进入预览与本机写入。

现有 APV1 本机库保持兼容；备份载荷版本独立管理。未来格式版本须增加明确读取/迁移器及样本，当前未知版本拒绝读取，不猜测或尝试降级解析。实现没有更换本机密码库加密策略，也不是 F08 的主密码功能。

验证使用虚构密码和隔离数据目录：`artifacts/vault-transfer-local-validation.json` 为 34/34，`artifacts/desktop-vault-transfer-validation.json` 为 24/24。迁移检查由两个 Windows CI 作业导出和导入；GitHub 镜像可能沿用相同机器名和 SID，因此导入作业在临时 VM 上创建不同 SID 的专用测试账户，载入其真实用户配置后运行，结束删除该账户。脚本限制在 GitHub 托管临时环境执行，不在用户电脑创建账户。源 DPAPI 文件不可读取、portable 备份导入、目标库重新打开和实际自动解压共 5/5；[最终 Windows CI](https://github.com/Nomoziya/nomozip/actions/runs/38279427184) 全部通过，证据见 `artifacts/github-validation-38279427184/vault-transfer-cross-import-validation.json`。
