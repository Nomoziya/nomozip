# 创建 TAR、GZIP 和 XZ

开发候选从 `0.2.0-preview.19` 起，压缩页沿用原有布局，在格式中增加 TAR、GZIP、XZ。默认仍为 7z；ZIP、加密、分卷、自解压的原有行为保留。

| 格式 | 可添加内容 | 压缩级别 | 密码 | 分卷 / EXE |
| --- | --- | --- | --- | --- |
| 7z | 多个文件或文件夹 | 支持 | 支持，包括中文及文件名加密 | 支持；EXE 与分卷互斥 |
| ZIP | 多个文件或文件夹 | 支持 | AES-256，ASCII 密码 | 支持分卷，无 EXE |
| TAR | 多个文件或文件夹 | 仅打包，级别禁用 | 不支持 | 不支持 |
| GZIP (.gz) | 一个文件，包括空文件 | 支持 | 不支持 | 不支持 |
| XZ (.xz) | 一个文件，包括空文件 | 支持 | 不支持 | 不支持 |

1. 添加文件或文件夹，选择格式和保存位置。
2. GZIP/XZ 不能直接容纳文件夹或多个文件；选择不符时显示具体原因并禁用创建。先创建 `.tar`，再单独添加这个 TAR，选择 GZIP/XZ，可得到 `.tar.gz` 或 `.tar.xz`。这是两个显式操作，没有自动删除中间文件。
3. GZIP/XZ 建议保存为原文件名加 `.gz`/`.xz`，例如 `资料.txt.gz`。新建 GZIP 不写可选的旧代码页文件名，避免跨系统乱码；这两种新建包的解压文件名来自包名去掉最后一个扩展名。重命名包也会改变解压名称。外部 GZIP 已有文件名字段仍按官方读取方式处理。
4. 切换到 TAR/GZIP/XZ 会关闭并清除本次加密密码、分卷和 EXE；回到 7z/ZIP 时不会自行重新启用加密。TAR 禁用压缩级别，原来选择的级别可在其它格式继续使用。
5. 创建写入同目录临时文件，官方引擎测试、格式/条目/路径/类型/大小清单核对后才交付；已有目标必须明确确认才替换。失败和取消保留原目标，清理本次临时文件。TAR 不含数据 CRC，结构/清单检查不等于提供逐文件内容哈希；需要哈希时可使用已有“文件 SHA-256”。

可在解压页浏览、完整解压或选择性解压生成的包。TAR/GZIP/XZ 的“修改内容”仍只读。解压 `.tar.gz`/`.tar.xz` 先得到 TAR，再添加 TAR 解压其内容；本期没有自动递归展开。

使用同一个官方 `7z.dll`，没有增加解码库或用户运行组件。创建 GZIP 省略文件名的依据是官方 [GzHandler.cpp](https://github.com/ip7z/7zip/blob/26.04/CPP/7zip/Archive/GzHandler.cpp) 的 `CP_ACP` 字段转换；单文件约束见 [XZ 更新接口](https://github.com/ip7z/7zip/blob/26.04/CPP/7zip/Archive/XzHandler.cpp)，格式能力见 [7-Zip 官方网站](https://www.7-zip.org/)。

`tests/FormatValidation` 使用实际 26.03/26.04 DLL 与官方命令行双向读写、精确字节、中文/长 TAR 名称、空文件/目录、独立 .NET TAR/GZIP 解码、真实文件锁、取消和错误清单检查。`--validate-formats` 在隔离库和不可见 WPF 窗口中操作真实格式下拉、创建、解压、替换拒绝，并复核普通/高对比度和窄窗口。报告为 `artifacts/format-validation.json` 与 `artifacts/format-ui-validation.json`。

未来官方引擎的维护候选必须额外通过格式矩阵，并将该报告与精确 DLL、worker、公钥一起绑定；未通过不启用或签发。当前原更新 ZIP schema / 五条目格式保留，新增证据进入原有签名兼容性记录。尚未对实际未来引擎版本作兼容承诺。
