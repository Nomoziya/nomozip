# 文件 SHA-256 与校验清单

属于 B2 / F19，本地开发候选 0.2.0-preview.7。公开正式版仍为 0.1.0，ZIP 文件名编码 F20 仍未实施。

在“设置 → 文件校验”点击“文件 SHA-256”。当前选中的压缩包会作为初始文件，也可以添加其它文件；不会自动开始计算。此功能计算文件原始字节的 SHA-256，独立于“校验压缩包”的包内数据验证。

添加文件后点击“计算 / 校验”。选择一行可查看和复制计算值，并粘贴可选的 64 位十六进制期望值；首尾空白和大小写不影响比较。空期望值显示“已计算（未比较）”，不能据此认为文件与某个来源一致。结果分别显示“一致”“不一致”“无法读取”，不把哈希结果称为病毒扫描或文件安全认证。

计算在后台按 128 KiB 缓冲区读取，进度显示当前文件、文件序号与字节数量，大文件不整块加载进内存。取消会释放正在读取的文件句柄；已完成行保留结果，未完成行没有计算值。再次计算会清除上次结果并重新读取。关闭正在工作的窗口会取消并等待结束；不会修改源文件、解压文件或密码库。

“导入校验清单”支持 UTF-8（可带 BOM）SHA256SUMS 格式，包括文本/二进制标记、CRLF/LF、中文/空格文件名及 GNU 的反斜杠转义。接受空行和以 `#` 开头的注释。路径相对清单所在目录解析，也支持绝对路径；完整路径可在列表提示查看。导入只展示文件及期望值，点击计算才读取内容。缺失文件会单独显示“无法读取”，不会被算作一致。清单出现坏行、冲突哈希、无效路径或编码时，原列表保留。

“导出计算值清单”只包含实际已计算的行，导出实际计算值，不是导入或粘贴的期望值。可导出部分完成结果；缺失和取消的文件不包含在内。使用二进制 `*` 标记，文件路径相对保存位置生成；同一卷的其它目录可包含 `../`，不同卷保留绝对路径。保存位置不能覆盖列表中的源文件。替换旧清单采用临时文件和原子替换，失败或取消保留旧文件。

首期只做 SHA-256；不支持 MD5、SHA-1、BSD 标记格式、Base64 或 NUL 分隔清单。清单最大 4 MiB、最多 10000 项。所有比较都针对文件原始字节，不做 Windows 文本换行转换。编辑期望值后可立即比较上次计算值；要核对文件当前内容，重新点击计算。

本地数据测试 34 项、实际窗口测试 43 项通过，覆盖已知空文件/abc/百万 a 样本、512 MiB 流式文件与平台流式 API 对比、受限分配、取消与句柄释放、清单格式/路径/错误/原子写入，以及真实按钮、粘贴、导入/导出、状态、小窗口整行可见和资源主题。窗口测试的剪贴板使用替身，不读取或覆盖用户的真实剪贴板；界面取消/关闭使用受控延迟，实际大文件取消由数据测试覆盖。物理多屏结论不由这些测试代替。完整 CI 记录见 [验收文档](ACCEPTANCE.md)。

开发验收发现并修复了进度控件错误尝试回写只读状态的问题；该异常曾令测试退出弹出普通任务确认框。现在进度只从模型读取，隔离 SHA-256 测试失败退出不使用普通任务退出确认；正常产品退出行为保留。

原始技术依据（2026-10-13 核对）：复用 [.NET IncrementalHash](https://learn.microsoft.com/en-us/dotnet/api/system.security.cryptography.incrementalhash?view=net-10.0) 与现有框架文件 API；清单参考 [GNU Coreutils checksum 输出格式](https://www.gnu.org/software/coreutils/manual/coreutils.html#cksum-output-modes)。无新增运行组件或外部加密库。
