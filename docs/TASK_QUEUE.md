# 任务队列

## 运行中暂停（0.2.0-preview.13）

运行解压时，底栏显示“暂停队列”。点击后不再启动排队项目，活动工作进程在下一进度、文件读写或操作回调处等待；引擎确认后行状态显示“已暂停”，进度条停止动画。按钮变为“继续队列”，继续时保留原进程与暂存文件。暂停中仍可“取消队列”，取消唤醒引擎、等待活动任务退出，再清理暂存和恢复操作。两个并发任务共用暂停请求，各自在检查点确认。

暂停是协作请求，不能保证点击瞬间停止 CPU/磁盘操作；已进入的系统 I/O 或一次文件交付会先完成，小任务可能已结束。密码/覆盖窗口已经打开时先处理该窗口；新的提示在队列暂停期间等待。取消仍采用整批语义，排队项保留。暂停中禁用跳过密码、重排、清理及并发设置，结束后清除暂停状态；完整成功后才保存密码记录。

范围仅当前进程内的解压队列。关闭软件时仍按既有确认流程取消并退出；不保存引擎内存、解码位置、密码或会话，也不支持跨重启续作。压缩、只读校验、浏览、软件更新和备份不显示暂停按钮。

复用官方 7-Zip 的 IProgress 和输入/输出流回调，自建条件变量检查点；控制消息只走父子进程管道，不使用进程强制挂起。托管队列和交付前也等待同一暂停门，取消独立生效。新增 pausable 操作名称使旧 worker 明确拒绝，不允许旧工作程序忽略暂停后误报正常。原有请求、压缩、编码和选择操作继续兼容。官方 SDK 说明进度回调可能来自其它线程，检查点与输出消息使用互斥协调；已核对 bootstrap 固定下载的官方源码 `CPP/7zip/Archive/IArchive.h` 与 `CPP/7zip/IProgress.h`。未来官方候选启用前增加暂停兼容矩阵，失败时保留 protocol 0。

证据：`artifacts/pause-validation.json`、`artifacts/pause-ui-validation.json`、`artifacts/pause-preview/`。检查包含实际 native worker 的暂停确认、进程身份/进度与文件大小稳定、继续后字节正确、暂停中取消、快速切换、旧 worker 拒绝、交付前覆盖等待及取消清理，以及实际 UI 按钮、双任务/排队项、密码记录不变、两种窗口尺寸和高对比度资源。完整 CI 与轻量包复核完成后更新验收记录。

## 受控并发（0.2.0-preview.12）

任务列表标题旁新增“同时处理”，默认 `1 个（顺序）`，可选择 `最多 2 个`，随设置保存；旧设置缺少该字段时保持顺序执行。运行中不允许改变上限或任务顺序。任务按列表顺序启动，完成顺序可以不同，每项的进度、密码、编码、输出和失败结果独立。

相同、互相包含的基础输出位置按顺序处理；输出位置包含另一个任务的源包时也不同时处理。每包/智能目录暂保守按基础输出目录预留，不在共同基础位置并发，避免目录编号分配或合并目标互相影响。不同基础输出位置最多运行两个任务，磁盘和内存开销取决于所处理的归档；并发不保证一定加速。

密码和同名文件提示共用一个异步入口，依次显示，不叠加多个窗口。“跳过尝试，输入密码”仅影响当前选中且正在自动尝试密码的任务；其它任务继续自己的候选流程。“取消”作用于整批活动任务，并阻止排队项开始；等待已启动的工作进程/任务退出后再恢复界面。取消密码窗口仍按既有整批取消语义处理。普通单项错误保留失败结果，其它独立任务继续；完整成功后才保存各自密码记录。已写入的成功结果保留，不将取消后的重做称为续传。

复用官方引擎工作进程、DPAPI 密码库已有写入互斥及原解压/来源流程；自主实现轻量任务调度器，用 Task.WhenAny 等待完成和 SemaphoreSlim.WaitAsync 协调交互，不添加产品运行组件。采用 ui-ux-pro-max 的 WPF 异步命令、捕获 UI 上下文与逐项进度建议。参考[微软异步协调原语](https://learn.microsoft.com/en-us/dotnet/standard/asynchronous-programming-patterns/async-coordination-primitives-advanced)。

隔离核心检查覆盖数量上限、顺序、路径重叠/源包保护、取消清理和失败清理；实际 WPF 入口使用官方 26.03/26.04 和合成归档，检查两个独立 native worker 同时运行、正确字节输出、共享目标顺序处理、取消、失败隔离、串行密码窗口、并发密码记录/关联、跳过隔离、设置兼容和普通/窄窗高对比度资源。证据为 `artifacts/queue-core-validation.json`、`artifacts/concurrency-ui-validation.json` 和 `artifacts/concurrency-preview/`；完整 CI 的 48 份报告均已核对通过，核心 37 / 界面 60 项。本地轻量载荷 9670273 字节 / 43 文件（增加 48982 字节），安装器 2259017 字节。四项本地候选资产位于 `artifacts/release-0.2.0-preview.12/`，复核见 `artifacts/concurrency-package-validation.json`。完整 [Windows CI 38442019776](https://github.com/Nomoziya/nomozip/actions/runs/38442019776) 和验收说明保留原有回归证据；未发布新正式版。

## 已验收的重排与单项操作首期

适用本地轻量候选 `0.2.0-preview.11`。公开正式版仍为 `0.1.0`，本轮不更换已安装程序。

解压页选择一个压缩包，点击工具栏的“任务操作”：

- “解压所选压缩包”仅处理所选任务；失败或取消后可以再次尝试，不顺带执行其它待处理任务。
- “上移所选任务”和“下移所选任务”调整顺序，保留任务自身的目标目录、ZIP 文件名编码和已有状态。列表第一项不能上移，最后一项不能下移。
- “移除已完成任务”只清理完成记录，保留待处理、失败及取消记录，源文件和输出文件不删除。

“开始解压”按当前列表顺序执行尚未完成的任务。列表不再按列头排序，避免显示顺序与执行顺序不同。运行中禁用队列修改；完成后恢复可用。已完成任务不能从该入口隐式再次解压，需要重做时移除记录并重新添加。

键盘可用 Tab 聚焦“任务操作”，Enter/空格打开，方向键选择、Enter 执行、Esc 关闭。标准 WPF MenuItem/Command 保留键盘和可访问性行为，样式沿用现有字体、颜色和焦点资源，窄窗工具栏换行。

本轮复用现有官方引擎、逐条密码处理、目录规则、冲突处理和下载来源标记的业务流程，没有新增运行组件。采用 ui-ux-pro-max 的 WPF Command 与键盘导航建议。范围对应规划 F07 的重排/单项操作子项；受控并发、运行中暂停与真正跨重启续作尚未实现，不把取消后的重新解压称为续传。

代理验收使用独立合成密码库、加密 7z 与 ZIP、官方 26.03/26.04，通过实际菜单 UI Automation 入口检查边界、状态保留、单项失败及重试、取消、运行中禁用、整批真实顺序及输出字节。菜单在普通/窄窗口检查入口可达、动态高对比度资源和可访问名称；逻辑焦点与 Esc 路由属于代理检查，不冒充物理键盘或真实讲述人复验。测试窗口和弹出菜单保持屏幕外，不读取实际密码库或改变系统主题。

证据：`artifacts/queue-ui-validation.json`、`artifacts/queue-preview/`。完整 CI 与候选包复核完成后，结果记录在 [验收说明](ACCEPTANCE.md) 和 [项目规划](../PROJECT_PLAN.md)。
