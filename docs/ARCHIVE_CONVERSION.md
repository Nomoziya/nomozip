# 归档格式转换

在解压页添加并选中一个压缩包，点击“转换格式”。选择新包保存路径、7z 或 ZIP、压缩级别；如需加密，勾选“加密新压缩包”，输入并确认新密码。7z 还可以加密文件名；ZIP 新密码沿用现有 ASCII 限制。原包密码不会自动成为新包密码。

首期转换普通 7z、ZIP、RAR 的全部内容。支持保存的源密码自动尝试、手动源密码以及同一源包中的多个密码；读取和转换不改密码库记录。不输出 RAR，不合并多包，不递归展开嵌套压缩包；空包、分卷、自解压包及其它输入暂不转换。这是重新压缩内容，不是改文件扩展名。

原包一直保留；新包不能使用原包路径。已有目标在明确确认后，只有新包完成验证才替换。正常失败和取消保留原包及已有目标，清理本次临时文件。原包在操作期间使用只读共享锁，阻止其他程序改写。原有来源标记传递到新包，不执行包内文件。

转换在目标目录创建独立临时目录：完整测试源包，解压并核对清单，重新压缩、测试新包，核对路径/类型/大小及所选加密，再次解压并逐文件比较 SHA-256 后才交付。补全隐式父目录并保留空目录/空文件；7z 的空文件无数据流，加密标记可能为否，不将此误判为非空数据失去加密。目录/文件内容和新加密设置是验收范围；不承诺跨格式保留注释、ACL、额外流或全部格式特有属性。

需要新包及约两份解压内容的临时空间。完成后普通删除临时明文，不承诺安全擦除或断电后的自动恢复；清理失败会显示目录，供手动清理。磁盘空间不足或不能写入时不交付未经验证的目标。

界面复用现有 WPF 卡片、动态主题、内部焦点框和固定底部操作；小窗只滚动设置区。支持简体中文、英语、浅色、深色和系统高对比度。没有新增运行组件，只准备共享运行库轻量版。

实现参考 [PeaZip 官方转换流程](https://peazip.github.io/peazip-help.html)，复用项目现有官方 7-Zip 读取/创建接口，没有引入 PeaZip 依赖或复制其源码。

验收入口：`tests/ConversionValidation` 使用两版真实 DLL 和官方 CLI 检查不同源/目标格式与加密组合、精确内容和空条目、不同源/目标密码、多密码源、RAR、NTFS 来源、取消、覆盖及真实共享锁失败，并拒绝内容被替换但可完整测试的候选。`--validate-conversion` 使用隔离测试库，通过实际工具栏和 UIA 按钮执行转换，检查双语、两引擎、三种主题、窄窗及密码清理。完整 x64 和原生 ARM64 CI 完成后以项目计划中的最终记录为准；未完成的物理体验验收不据此宣称通过。

引擎维护加入第十一类 `conversion-validation.json` 矩阵。候选准备、复核及签发均要求目标版本覆盖、实际 DLL 摘要和完整通过结果，十一份报告及引擎/worker/公钥共 18 项绑定；兼容记录仍在既有 RSA 签名载荷内，更新 ZIP 五条目格式不变。
