# 仓库文档维护约定

README 面向第一次访问项目的使用者，按“简介 → 下载与依赖 → 当前正式版功能 → 快速开始 → 文档与反馈”组织。参考 [NanaZip](https://github.com/M2Team/NanaZip) 和 [PeaZip](https://github.com/peazip/PeaZip) 的项目首页结构，只借鉴信息组织，不复制产品声明、许可或商标。

- 首页只概括当前公开正式版。开发候选以一段状态说明和文档链接呈现，不能混入正式版功能列表。
- 新功能和操作说明写入对应专题，通过 [文档索引](README.md) 连接；README 不逐次追加预览版段落。
- 发行变更写入 GitHub Releases；测试数量、CI 链接、失败分析和代理交接写入验收或项目记录，不放在首页堆叠。
- 下载链接必须对应实际公开资产。正式版发布时同步版本、架构、运行库要求和体积，不将引擎更新包当软件安装包。
- 示例使用相对路径、环境变量或明确的示例目录，不写入开发者个人目录、真实密码、个人邮箱、令牌、私钥、密码库和用户日志。
- 公开提交使用 GitHub 隐藏邮箱；`.tools/`、`artifacts/`、本机凭据和用户数据保持在发布范围之外。源码包仍使用显式允许列表。
- 维护记录保留在已有文档及 Git 历史中，不为清理首页重写历史或覆盖旧发行资产。若发现真实凭据泄露，先撤销凭据，再单独处理历史和发行资产。
