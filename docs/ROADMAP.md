# 后续任务与相关产品研究

基线：正式版 0.1.0，产品提交 `1059801bcb125f6da6e7abc4ca0a42dc4b4f9be3`。用户已要求把上一轮建议加入后续任务，并继续搜索相关产品、筛选应加入的功能。本文件是后续任务的统一清单；开发及验收状态见文末，不代表正式版已经支持，也不要求一次全部加入下一发行版。

沿用 C#/.NET 10、WPF MVVM、C++ worker 与官方 7-Zip 引擎。主会话和执行者均为 gpt-6.1-sol / high，本轮已核实，无子代理；后续开始工作包时按项目规划轻量核对。界面开发继续应用 ui-ux-pro-max，以操作清晰、信息层级、视觉一致性为优先。只发布共享运行库轻量版，比较新增功能前后的载荷、启动和运行开销；优先使用现有 .NET/Win32/7-Zip 能力，新增依赖须说明必要性与体积影响，不承诺扩展后字节数完全不变。

## 研究依据和选择

本轮查看了下面产品的官方说明与仓库，并对照当前源码。表中的接入方式、成本和优先级是针对 nomozip 的判断；没有把竞品介绍当作本项目已经实现或实测的结果。

| --- | --- | --- |
| [7-Zip](https://www.7-zip.org/) | 命令行、Shell 集成、更多写入格式、7z 自解压 | 继续直接使用官方引擎，按格式补齐界面与专项验收；不因新增功能维护一份自改引擎。 |
| [NanaZip 官方仓库](https://github.com/M2Team/NanaZip) | Windows 10/11 右键菜单、智能解压、完成后打开目录、每显示器 DPI、深色模式、下载来源标记传播 | 借鉴操作与适配目标；保留当前 WPF 和轻量安装方式。现代右键菜单单独评估包身份与 Shell 组件，不整体移植其 UI/分发栈。 |
| [PeaZip 功能说明](https://peazip.github.io/peazip-free-archiver.html)、[哈希工具](https://peazip.github.io/verify-checksum-hash.html)、[转换归档](https://peazip.github.io/convert-files.html) | 校验和、归档转换、内容编辑、脚本自动化 | 借鉴工作流；哈希直接使用 .NET，转换复用现有解压/创建流程，自动化提供产品命令接口。避免捆绑多个后端以复制其全部功能。 |

专项来源：

- [Bandizip 智能解压](https://www.bandisoft.com/bandizip/help/auto_dest/)与[PeaZip 智能目录](https://peazip.github.io/how-to-extract-rar-zip-archives.html)：用于 F05 的目录决策。

- [Bandizip 代码页识别说明](https://www.bandisoft.com/bandizip/help/codepage-autodetect-problem/)：自动识别是估算，F20 首期保留手动选择与预览。
- [Bandizip 下载来源标记](https://www.bandisoft.com/bandizip/help/zone-identifier/)：用于 F24，不等同于内置杀毒扫描。
- [微软现代 Explorer 菜单接口](https://learn.microsoft.com/en-us/windows/apps/desktop/modernize/integrate-packaged-app-with-file-explorer)：原生 Windows 11 菜单涉及 IExplorerCommand 和包身份；保留现有应用栈，不能按“写几个注册表值即可”估算。
- [Bandizip 非英文密码说明](https://www.bandisoft.com/bandizip/help/how-to-use-non-english-password/)：也限制 ZIP 创建的非英文密码并建议 7z。当前 ZIP 创建的 ASCII 限制保留；文件名乱码处理和密码编码是不同问题，不用 F20 暗示放开密码限制。

## 不加入当前实施队列的能力

- 云同步、账号系统、插件市场与跨平台重写：保留观察，当前本地轻量定位没有直接需求。
- RAR 创建及 RAR 恢复记录：官方 7-Zip 当前为 RAR 读取路线，不捆绑 WinRAR 或另一个商业后端来改变产品依赖。
- 暴力密码恢复、通用压缩包修复、内置杀毒引擎：不是“保存用户已知密码并可靠处理归档”的小范围扩展，不承诺复制竞品全部能力。
- ZIP 创建的非 ASCII 密码直接放开：保持现有兼容策略，需要非 ASCII 密码时使用已支持的 7z；今后有明确需求再按跨工具样本研究。
- 删除原始压缩包作为默认成功动作：本轮未列入目标，成功后优先提供结果入口。
