# 修改已有压缩包

开发候选 `0.2.0-preview.16` 在“查看内容 → 修改内容”提供 7z/ZIP 的添加、删除和替换。RAR 及其它格式仍只读。

- 添加文件或文件夹到包根目录，文件夹包含子项和空目录。与已有包内路径冲突时停止，不静默覆盖。
- 勾选一个包内文件后可“替换所选文件”，本地文件沿用原包内路径。替换文件夹暂不支持。
- “删除勾选内容”包含勾选文件夹的全部子项，搜索隐藏的勾选项也计入确认数量。
- 每次修改前确认范围；先完整测试原包及验证密码，再生成同目录临时新包。新包须完整测试并核对条目路径、大小、类型、加密标记；加密文件名保持加密，全部通过后才原子替换。
- 成功后内容列表自动刷新，清除旧选择和旧解压/验证状态。原包旁保留 `<原包路径>.before-edit-<随机标识>.bak`，包含修改前的全部字节和已删除/替换的内容。需要恢复时关闭软件，将副本复制到新的 `.7z`/`.zip` 文件；确认正确后再自行替换原包。
- 修改不保存新密码或更新密码库记录；原包和副本原有 NTFS 下载来源标记保留。临时新包不经过整包解压到磁盘。

新增/替换文件使用本次完整验证的密码，已有条目沿用官方更新接口保留其数据及属性。7z 固实块可能由官方引擎重新压缩，新增数据使用普通压缩级别；不承诺包字节、大小、压缩参数或第三方扩展属性完全相同。目录、文件内容和加密状态经专项测试。仅浏览不会启动修改。

当前边界：多个密码的包可继续浏览和解压，暂不修改，避免推定新文件应使用哪个密码。ZIP 新增加密数据仍要求 ASCII 密码。官方引擎将加密文件名的 7z 删空后会失去文件名加密，因此软件阻止删空这种包，原包保留。普通空包与无加密文件名的包可删空。路径冲突、不安全路径、链接、过期内容列表、取消、错密、临时包损坏或提交失败均不能交付新包。

实现采用仓库已有官方 SDK 的 `IOutArchive.UpdateItems` 和 `IArchiveUpdateCallback`（[官方源码](https://github.com/ip7z/7zip/blob/main/CPP/7zip/Archive/IArchive.h)）：未修改条目以 `newData=0/newProps=0` 保留，写入项提供新数据与属性。沿用 C# WPF MVVM、独立 worker 和官方 DLL，无新增运行组件。

验收：实际两版官方 DLL、官方 CLI 解压后的精确内容、固实/加密文件名 7z、明文/AES ZIP、原始备份字节、路径冲突、错密、RAR 只读、多密码拒绝、取消、候选损坏、真实共享锁导致提交失败、NTFS 来源及空包边界。界面从正式“查看内容”入口和真实菜单命令验证，使用隔离合成数据、不可见窗口，测试小窗口与高对比度；不更改已安装软件、用户库、注册表或系统缩放。报告 `artifacts/archive-editing-validation.json` 和 `artifacts/archive-editing-ui-validation.json`，完整 CI 和最终体积以计划记录为准。

未来官方引擎升级须额外通过修改矩阵，候选维护绑定六份报告及 worker/固定公钥，缺少或篡改修改证据不得签发。Windows 代码签名仍不在验收范围，引擎更新真实性校验保留。
