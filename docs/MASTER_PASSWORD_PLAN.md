# 主密码与空闲锁定审计（F08，尚未实现）

本文件记录下一工作包的源码审计与实施方案。2026-10-14 用户已选择通过事先导出的独立加密备份恢复，不增加重置通道；现有功能、密码库格式及正式版不因规划改变，本项尚未实现。

## 现状

- `DpapiPasswordVault` 使用 APV1 文件头和 Windows DPAPI CurrentUser 保护整份密码记录与文件关联；写入为临时文件与原子替换，`.bak` 保留上一份。没有主密码密钥或锁定状态。[微软 ProtectedData](https://learn.microsoft.com/en-us/dotnet/api/system.security.cryptography.protecteddata?view=net-10.0) 说明此 API 使用 Windows DPAPI；其当前用户保护不等于应用主密码加密。
- `EncryptedVaultBackup` 已用 PBKDF2-SHA256 / AES-256-GCM 生成独立口令的 `.nvault`，有随机盐、nonce、验证标签、取消清理和跨 Windows 用户验证。可以复用现有 .NET 密码学能力及数据验证规则，无需新增用户运行组件；备份容器并非现用密码库，不能简单替换类名就声称完成。
- `MainViewModel.allPasswords`、密码列表、手动密码对话框和 `PasswordCandidateProvider` 会持有或再次读取密码。解压、浏览、选择性操作、压缩后保存、导入导出、合并和恢复均访问库；锁定必须贯穿这些业务入口，不能只盖住密码库页面。

## 建议实施规则

不开启主密码时保持现有 APV1 行为。启用主密码后使用版本化、经认证加密的本地格式；主密码派生密钥实际参与解密，Windows 登录本身不能绕过。优先沿用现有 .NET AES-GCM / PBKDF2 能力，具体容器和参数须在数据层原型中验证；GCM 的 nonce、认证头、错口令和损坏拒绝由实际文件测试证明。原始 API：[AesGcm.Encrypt](https://learn.microsoft.com/en-us/dotnet/api/system.security.cryptography.aesgcm.encrypt?view=net-10.0)、[PBKDF2](https://learn.microsoft.com/en-us/dotnet/api/system.security.cryptography.rfc2898derivebytes.pbkdf2?view=net-10.0)。

迁移先验证新加密文件，再原子提交；取消、错误口令和写入失败保留旧状态。启用成功后的活动库与应用自动恢复副本都需要主密码保护，不能留下可由同一 Windows 用户直接解密的旧格式副本。用户之前自行导出的备份独立保留；文件系统历史/旧外部副本不属于本功能可追溯重新加密的范围。更改或关闭主密码必须先成功解锁，不通过删除设置重置库。

锁定后清空列表与应用缓存，拒绝自动取用、编辑、保存、导入导出及库恢复；非加密解压和不保存的手动密码操作仍可用。已传给正在运行 worker 的密码不能撤回，首期在任务结束后完成空闲锁定，期间避免启动新的库操作；真实 Windows 会话锁定等额外触发另按实际需求确定。可清空的密钥/字节清空，释放字符串引用，不承诺托管字符串或既有 worker 密码立即从所有内存消失。

## 已确认的恢复方式

使用独立加密备份恢复，没有内置主密码重置通道。忘记后用事先导出的 `.nvault` 及其独立备份口令恢复到新库；没有可用备份则无法恢复原库，备份之后的新记录也不在其中。恢复入口需要核对备份内容和确认创建新库，不能以清空设置代替原库解密。原锁定文件的保留/替换流程在数据层原型验证后形成可检查操作。

不增加离线恢复码、Windows 登录重置或云端恢复；不实现仅界面锁定来代替本项的文件加密目标。当前 F09 的验收仍独立完成。
